# Presence impact assessment

Inside Testing and diagnostics, **See Presence impact** explicitly sends the selected evidence to Muse Spark 1.3 through Meta and displays its assessment. Selected exchanges and code may contain private task data or embedded credentials; secret filtering is not comprehensive. Rendering, typing, new readings and turn completion do not start an assessment. The action is available after task activity settles. The existing layout and action are retained.

The primary view contains a short takeaway, a compact usage graph and one selected comparison with **Muse** and **Muse + Presence** excerpts. New assessments with public replies cover four fixed lenses: **Density**, **Interruptions** (including held optional updates, separately), **Conversation** (self-contained versus conversational) and **Presentation**. **Work** is an optional fifth finding for a material difference. An unchanged behavior or local evidence gap is also a finding. The assessment considers:

The reference is the recorded Presence policy at the relevant task step, rather than a universal communication-quality ranking. Findings follow **observed contrast → applicable policy → alignment or departure**. A shorter handoff can fit terse guidance; expanded explanation can fit full guidance. Explicit boundary lists versus an implicit short summary are differences, not evidence that one agent is better or deeper on correctness. Recorded work/check outcomes and resource totals remain factual comparisons, separate from communication fit. Policy changes are considered at their own task steps; the baseline is never assigned the adaptive arm's policy.

- **What:** answers, completed work, correctness checks and unresolved issues.
- **How:** communication, reasoning, feedback incorporation and Presence guidance.
- **When:** response/feedback order, turns, interruptions, update timing and elapsed time, interpreting resource use alongside that work and interaction.

Each highlight explains the difference and its relation to the relevant recorded Presence guidance before showing the evidence. Only one explanation and paired excerpt are shown. Controls stay in a fixed order and preserve focus; absent lenses in historical assessments are disabled and explicitly labeled as not covered. Long saved paragraphs and explanations show bounded literal previews with expansion to their complete unchanged text. Excerpts use the actual terminal Markdown renderer, preserving original line breaks, headings, lists, emphasis and code. The model selects a normalized literal substring; the UI restores the exact original source span. Excerpts cannot be rewritten or borrowed from the other arm. Turn labels require actual completion links.

The UI uses native DOM and the app's existing theme, without React/Lucide dependencies. Missing-text packets show one material coverage state and the available overall comparison. No excerpts are fabricated. Metric pairs wrap at narrow widths and chevron transitions respect reduced motion.

One-sided exchanges are allowed when the extra or missing input is explained. An absent counterpart is shown explicitly; another unrelated reply is not forced into that side. Reference comparisons do not imply identical instructions or simultaneous responses.

The takeaway names the work result and meaningful resource tradeoff. A quiet paired-bar graphic shows completed turns, model calls, input/output tokens and recorded turn time from the assessment's saved evidence. Each metric has its own shared pixel scale. Cache reads are hatched within input; an unknown or inconsistent split has a distinct outline and local marker. Missing totals are dashes, actual zero stays zero, and partial time is labeled. The Details table adds cache reads and input minus cache reads. Lower total input can coexist with higher input minus cache; counts do not establish dollar savings. Coding-session metrics and observer usage remain separate. There is no generic attribution warning below the main view. Recorded controls describe collaboration guidance; explicitly reported personal states remain reports.

One collapsed **Details** disclosure holds evidence JSON, source controls, recorded guidance, usage, coverage and the observer's attribution note. Duplicate live comparison and legacy telemetry panels are hidden in rich-report mode. Earlier reports can display concrete guidance changes and saved reference completions without changing their original Muse paragraph.

## Evidence and JSON contract

The concise generation profile enforces the brief at the source: overall at most **240 characters / 35 words**, explanation **160 / 22**, title **60 / 8**. The provider schema carries character caps; local validation also enforces whitespace-delimited word limits and required lenses. Rendering does not make another call or rewrite historical outputs. The default historical v2 reader retains its broader limits and permits partial old assessments; v1 remains separate. Quiet excerpts use the same inert terminal renderer, with policy references, timestamps, input coverage and detailed telemetry in **Details**.

Only the server builds the opaque packet. Its internal preview is a detached copy, expires after five minutes and can be consumed once. Generation rechecks session scope and work hashes. The explicit assessment action uses the same opaque server preview and generation. The server rechecks current scope and work hashes before sending; previews expire and can be consumed only once. This is not comprehensive secret detection. No separate packet-review action is required by the current flow.

The packet is capped at 48,000 UTF-8 JSON bytes, with whole-record omissions and coverage metadata. It contains public exchanges, selected work, Presence requests/readings and native public-completion links, supplied checks, resource readings and closed interaction evidence. First planning/question responses and the latest handoff are prioritized with their native request links when available. Offline adapters may pass structured `archivedRequests` from verified exports; these are sanitized, labeled `saved_export`, retain original turn/request ordinals and never create native completion links. Native/current tuples take precedence. It excludes private native streams, hidden reasoning, raw typing, Capsules and instruction files.

File selection excludes hidden/private directories, environment files and credential-like filenames. This filename filtering does not inspect selected message or source contents for embedded secrets. Selected exchanges and work files can contain private task data or credentials and are sent to Muse through Meta when the assessment is requested. Secret filtering is not comprehensive; the separate export redaction does not protect this model request.

Interaction records separate participant/coordinator/unattributed receipts, steering, interruptions, question replies, approvals, completed/incomplete turns and self-reports. Client-reported browser views describe optional-update holding/release and retained display-event timing; views are not additive. Unknown values remain null. Public indexes provide sequence, not per-message native timestamps.

New generation returns closed **schema_version2** JSON: `highlights` and `overall`. Each highlight has a unique `category`, `title`, `explanation:{text,evidence_ids}`, `policy_ids` and own-arm `without`/`with` quotes containing `message_id` and `excerpt`. The concise profile requires depth, interruptions, turns and format when public replies exist; content is optional. Without public replies, highlights remain empty. Quotes retain their 260-character cap. At least one quote is real; a `none` counterpart has an empty excerpt and requires explicit differing/single-arm context when that arm has other replies. Each highlight selects one to four known With policy records. Overall references include input comparison, both telemetry and interaction records, Presence and each arm's file or unavailable-work status. At most 64 distinct references are allowed. Source quotes and generated prose render inertly.

The beta generation path separates **model-selected citations** from **server-owned snapshot context**. Its runner and service use `grounding: snapshot_context`; selected IDs remain known, nonempty and bounded, with unchanged literal-quote and request-policy guards. The app independently checks comparison, both telemetry/interaction records, Presence and both work statuses on the opaque packet, adding selected file context when available. It attaches these IDs as `snapshot_context` outside the model report. It neither adds citations to the model's arrays nor rewrites its words. The default historical `model_references` validator retains the stricter overall citation requirements described above. Snapshot context is context, not certification that every interpretation is correct.

`responses.comparison` gives typed final/commentary message counts, total whitespace-delimited public words and mean words per message. Sources distinguish complete text, reported saved counters, captured subsets and unknowns; complete-text conflicts are explicit. Per-message word rows refer only to retained message IDs. `packet_text` describes text actually retained in the packet, separately from source completeness. Whole-recorded-snapshot means are not matched-turn or policy-interval means. For example, 686 words across three finals has a slightly higher mean than 911 across four: lower total words does not establish shorter replies. Counts alone cannot establish conversational style, presentation or information density.

Moment candidates are derived from ordered With requests or timestamped readings with an actual changed control. A linked reply change requires distinct exact before/after completion links. Each moment and its dependencies enter the byte budget atomically. Source times, request controls, native linkage, available public replies and independent baseline references remain separate. Task-description prose and equal text are not promoted into native authority.

If a With final has an exact completion link, its selected policy must be its actual request, matching reading or explicitly linked moment. Current controls and another turn's request cannot replace that policy. Without exact binding, an assessment may explain a supported contextual fit without inventing a temporal join. Equal text, task prose and turn ordinals do not establish native authority. Historical v1 reports retain their separate reader; new live generation rejects a v1 response. Assistant test and reproduction claims remain distinct from supplied hash-linked checks.

Historical closed check results retain dates, hashes, pass/fail counts and stale/consumed lifecycle; missing source does not make them current checks. Final work is retained in memory before cleanup. End-state files do not establish which historical generation changed code. Packets/reports remain outside scrubbed exports and Git, with at most three in-memory reports per comparison.

## Freshness and execution

New exchanges, work, substantive elapsed/interaction records, completed review segments, ratings and current-generation display evidence invalidate a snapshot or mark the assessment outdated. A running review clock is frozen at request time so ordinary ticking cannot block generation. Unused Presence readings and clean closure do not invalidate completed work.

The existing Meta/Muse Spark 1.3 observer uses one empty-preset, contributor-off attempt/step, a 120-second timeout, no tools/provider retries, and no OP or evaluator calls. Observer usage is separate from the coding pair, including failed/cancelled attempts. Cost remains unavailable when unreported. Only the user's action invokes this path.

## Verification and activation

Offline checks cover literal quotes and original formatting, one-sided highlights, policy binding, cache counter reversals, privacy, historical checks, interaction/display projections, one-use snapshots, measurement freshness, cancellation, click ordering, session-change blocking, inert rendering and authenticated routes. Exact isolated regression and browser results are recorded separately.

Offline checks cover the projection, literal grounding and freshness mechanisms. Structural validity does not establish semantic correctness or measured benefit. The revised assessment prompt has not had a new provider-backed qualification.

Restarting the local backend ends its native conversations. Save evidence and any draft first; do not restart while work is active.
