# Project guidance

Read the README, setup and qualification status before changing the workspace. Preserve the distinction between implemented behavior, offline tests, real-provider observations and measured human outcomes.

Presence guidance is temporary. Keep the baseline isolated, re-check freshness at the existing request boundary, support withdrawal and ordinary fallback, and never infer numerical personal state or permanent preferences. Presence does not grant permission or reduce correctness requirements.

Keep normal Muse sandbox and human approvals. Do not automatically approve actions or change collector, inference or packaging as part of harness work. Preserve open sessions, drafts and evidence before a restart. Run focused offline checks for changes and retain relevant neighboring behavior.

Never add real typing, Capsules, native transcripts, local evidence, Muse credentials or other private credentials to source. The sole designated submission exception is the temporary `judge-access/temporary-credentials.json` OP-only evaluation bundle; do not add npm tokens, other credentials or private Cipher packages. Public Cipher installation must not read the OP bundle or depend on an npm login. See `judge-access/README.md` for scope and expiry. Treat model, OP and evaluator calls as explicit actions with appropriate authorization. Reviewed redacted real-run snapshots may be prepared under evidence/runs using the closed projection, retaining unknowns and provenance. Review them before any Git inclusion; raw originals remain private.

Keep the pinned, owner-authorized Agent Lab/Pulse and Capsule validator snapshots and their manifests and notices intact. Do not claim that inherited foundations were built during the event. See `docs/PROVENANCE.md` and `docs/DEPENDENCIES.md`.

This clean GitHub history is the canonical submission/product source. Integrate
only reviewed, selected file changes; never merge or import private development
history, work logs, unapproved evidence or additional credentials. Hosted wrappers,
their CI, infrastructure/configuration and deployment credentials belong only to
the dedicated private GitLab hosting branch. Do not copy them here or replace this
repo's qualification CI with deployment CI. Coordinate shared-interface changes
with the hosting owner before porting them. Synchronization means verified bytes
for an explicit shared scope, with audience-specific docs and access kept separate;
it does not mean identical histories. Keep publication and runtime changes separate.
